## 各平台特色

### Telegram — 功能最全
- Bot API 最成熟，几乎所有功能都支持
- Inline buttons 让用户可以直接点击操作
- 支持消息编辑、Topic 分组
- 大文件传输（最大50MB）
- 语音消息自动转文字 + TTS原生气泡显示
- **缺点**：国内需要梯子

### 微信 — 覆盖面最广
- 用户基数最大，国内最常用
- 通过 iLink Bot API 连接
- **限制**：不支持按钮交互、不支持消息编辑、MD部分支持、文件大小有限制
- 需要本地代理才能连接（DNS问题常见，详见 SKILL.md gateway troubleshooting）
- **优点**：用的人多，触达率高

### 飞书 — 企业级最强
- 卡片消息（富交互），可以做漂亮的交互界面
- **独特能力**（需配置权限）：自主创建多维表格、云文档、日程、审批流
- 权限管理完善，适合企业协作
- **缺点**：主要在企业场景使用，个人用户少

### QQ — 最受限
- 通过 go-cqhttp 等第三方框架
- 功能支持有限，媒体发送不稳定
- 主要用于社区/群聊场景

### Discord — 社区最强
- Embed消息可以做漂亮的卡片
- 支持按钮、下拉菜单交互
- 频道+线程组织清晰
- 适合技术社区、开源项目

## 应用场景推荐

| 场景 | 推荐平台 | 原因 |
|------|----------|------|
| 个人日常助手 | 微信/Telegram | 用的多，触达方便 |
| 企业协作 | 飞书 | 可操作文档、表格 |
| 技术社区 | Discord | 频道组织清晰 |
| 定时任务通知 | Telegram/微信 | 确保能收到 |
| 复杂交互 | Telegram/Discord | 按钮支持好 |

## 讲课/分享要点

1. **同一个Agent，多个入口** — 记忆、技能、定时任务全局共享
2. **平台能力决定交互方式** — 微信只能纯文本，Telegram可以有按钮
3. **飞书的独特价值** — 不只是聊天，还能操作文档/表格
4. **选择建议** — 根据用户在哪就用哪个，功能差异可以用其他方式弥补

## 技术架构

```
用户消息 → Gateway（统一入口）→ Agent（同一个大脑）→ 各平台适配器
```

- **共享层**：Memory、Skills、Cron、Tools
- **隔离层**：对话历史（各平台独立，不互通）
- **投递限制**：定时任务只能单平台投递，多平台需创建多个任务
